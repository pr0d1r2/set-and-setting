# MoSCoW method

Prioritize requirements and tasks using four categories:

- **Must have** -- non-negotiable for the current delivery. Without
  these the release has no value or violates a constraint. If a must-have
  cannot be delivered, the delivery fails.
- **Should have** -- important but not fatal to omit. Workarounds exist.
  Include unless a must-have is at risk.
- **Could have** -- desirable if time and effort permit. First to be
  dropped when capacity is constrained.
- **Won't have (this time)** -- explicitly out of scope for this
  iteration. Recorded so stakeholders know the item was considered and
  deferred, not forgotten.

## Applying the method

Classify every item before starting work. When scope pressure appears,
protect must-haves by shedding could-haves first, then should-haves.
Never shed a must-have to accommodate a lower-priority item.

Record the classification visibly (spec, issue, or task list) so the
priority contract is explicit and reviewable. Re-evaluate when
constraints change -- an item may shift categories between iterations.
