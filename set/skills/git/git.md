# Git

Commit successful work in small, atomic steps.
Keep separate topics in separate commits, including independent refactors.
Use each commit as a durable work record: state what changed, why it matters,
and the check or evidence that supports it in concise, factual terms.
Treat the commit history as durable project memory and an audit trail of the
work, not as a transcript of private reasoning.
Small, focused commits keep each change easy to review, revert, and verify,
and reduce the chance that unrelated staged changes hide a mistake.
