# Design paradigms

Recurring structural patterns that shape how software is designed,
decomposed, and extended. Each paradigm provides a lens for evaluating
design decisions -- naming, defaults, boundaries, coupling, information
flow -- and a bias toward designs that satisfy the paradigm's core
constraint.

Apply paradigms during interface design, API surface review, module
decomposition, and any decision where multiple correct designs exist.
When paradigms conflict, state the trade-off explicitly and choose the
one that best serves the user of the interface.
